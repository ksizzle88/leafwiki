# My Development Preferences

This file contains your personal coding style and preferences that apply across all projects.

## Code Style
- Write clean, readable code with descriptive variable names
- Prefer functional programming patterns where appropriate
- Keep functions small and focused on a single responsibility

## Error Handling
- Always include proper error handling for async operations
- Log errors with sufficient context for debugging
- Use try/catch blocks for operations that may fail

## Testing
- Write tests for new features and bug fixes
- Use descriptive test names that explain what is being tested
- Aim for meaningful test coverage, not just high percentages

## Documentation
- Document complex logic and non-obvious decisions
- Keep comments up-to-date with code changes
- Prefer self-documenting code over excessive comments

## Git Commits
- Write clear, concise commit messages
- Use conventional commit format when applicable
- Keep commits focused on a single logical change
